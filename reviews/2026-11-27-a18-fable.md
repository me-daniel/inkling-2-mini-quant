## Reply (verbatim)

Review of Addendum H amendment 18 (direction). Labels: [R] measured-in-record, [I] my inference, [S] needs a source.

Verdict: run it, but narrower and re-ordered. As drafted, the costly parts inform the card wording, and only the optional item 4 informs the method.

A. Is this the right test now?

1. The "closest" claim is already contradicted. Unsloth UD-IQ3_XXS is 5-12% closer than v2c on fresh code [R]. Beating ISTA would not restore "closest", and losing adds a second file to a correction that is already due [I].
2. The backlog consequence is mostly decided too. Our refiner fixes scales, GSQ learns them jointly, and the one public file that beats us differs in more than codes [R]. T2 is the obvious next step whatever P1 shows [I].
3. The outcome that would change a decision is "ours closer at equal bytes": then T8 and GSQ-chasing can be dropped [I]. The contract gives that outcome only a card line.
4. Item 4 (attribution) is the only part that says whether to work on the map or the encoder, and it is "if cheap". Make it mandatory if ISTA wins P1, and fund it by cutting tasks [I].

B. What is missing that would change a decision

1. Unsloth UD-IQ3_XXS is not scored on A3. Without it, no outcome supports or retires "closest". It costs one more file [I].
2. No size adjustment. ISTA's four files give a KL-against-bytes curve from 8.98 to 11.43 GB [R]. Pre-register "our file against ISTA's curve interpolated to our bytes (log KL, linear in GB)" as a co-primary. A 1.2% byte gap can be a few percent of KL at this size [I], the same order as the effects in our record.
3. No margin. A CI of [0.97, 0.995] triggers a correction, and [0.85, 1.15] reads the same as [0.98, 1.02]. Add a band, for example: a win needs the bound beyond 1 and the point estimate beyond ±3%; a tie needs the whole CI inside ±5%; anything else is "underpowered" [I].
4. R is an arithmetic mean of geometric means. Use the geometric mean across domains, or R is biased upward and asymmetric under swapping numerator and denominator [I].
5. Twelve documents per domain is a small number of clusters, so the bootstrap CI will be too narrow [I]. Report the per-domain sign count (5 of 5, 4 of 5) beside R.
6. "P1 or P2" pools two projects, and mixed outcomes are undefined. Write the actions per pair [I].
7. The reference is our own Q8_0, built in our pipeline, and ISTA's reference is unknown [R]. Any bias should be small against 3-bit error, but it leans our way and cannot be checked, since the BF16 does not fit in 48 GB [I]. State it on the card.
8. A3 is raw documents only. It has no chat-template or tool-call text, which is how the model is used, and the 300-item battery cannot see under 8-10 points [R]. A sixth domain of chat-formatted transcripts would matter more than the english or math split [I].
9. Domain asymmetry: english is near S, which selected our files [R], and javascript is outside our calibration but possibly inside ISTA's [I]. Pre-register R without english as a sensitivity result.
10. The geometric-mean ratio hides tails. Add the 99th-percentile per-token KL and top-1 agreement from the same logits, at no GPU cost [I].
11. Attribution is confounded. "ISTA / ISTA-map-stock" includes ISTA's calibration data as well as its encoder [I]. Call it "encoder plus calibration".
12. Check that tokenizer, chat template and metadata match across files before scoring, or KL measures packaging [I]. Whether IQ1_S and IQ3_S types cost Metal speed needs a source or the bench [S].

4. Tasks last, only for a pair whose KL result is a tie. A task run for a pair with a clear KL winner changes nothing [I].
