## A. Hypotheses H1–H5

1. **H1 · Pass count and error growth. Est.** The directional prediction is identifiable for this checkpoint and runtime. The “once, once per visit, or compounding” interpretation is unidentifiable from the KLD curve. Locally, KLD is quadratic in logit perturbations. Identical additive errors can produce quadratic KLD without feedback amplification, while opposing errors can cancel. Each pass count also changes reference logits, routing, and the state read by the coda. **V.** Varloop saw all five counts during midtraining, with unequal exposure, and received RL at three. Inkling restarts each pass from the same prelude output and transmits information through gated messages. **Est.** A B1 intervention therefore changes the input supplied to every pass. It cannot by itself test the fixed-point account in *Tilted Bowl*. [Varloop model card, 20 Nov 2026](https://thinkingmachines.ai/model-card/tml-d24-varloop-research/) · [vLLM architecture, 20 Nov 2026](https://vllm.ai/blog/2026-11-20-inkling2-mini) · [Tilted Bowl, 30 Sep 2026](https://arxiv.org/abs/2609.39277)

2. **H1 · Falsifier and cheaper design. Est.** Predeclare one contrast: the P=1 to P=3 increase for a looped intervention minus the increase for a matched-size once-executed NVFP4 intervention. Use an equal-layer control drawn from B4 and keep B5 separate. A paired upper confidence bound below the prespecified meaningful increase falsifies the directional claim at that margin. Start with one quantizer, P=1/2/3, and one exploratory P=5 check. Hold the quantized tensors and scored prefixes fixed across P. At fixed P=3, switch the same perturbation on for the first, middle, last, or all visits of one core block. That directly tests where error enters and whether it persists. If visit switching fails, report a pass-count interaction and drop the propagation claim.

3. **H2 · Pooled versus first-visit calibration. Est.** Well posed after defining “first visit” as visit one of the **same P=3 forward pass**. Standard pooling can win through greater sample count or better expert coverage. Compare first-only, all-visits with an equal observation budget, and RTN or a format-compatible unweighted baseline. Log visits and expert counts, including unseen experts. Hold formats and tensors fixed and score on held-out documents and prompts. A confidence interval ruling out a meaningful pooled reduction falsifies the practical claim. Cheapest test: one core block, one deployable format, one P. **V.** Upstream imatrix code adds squared activations by weight name and expert when the callback sees `MUL_MAT_ID`. **Verify.** Confirm that the pinned Metal graph exposes every visit and the intended input. [llama.cpp imatrix source, checked 21 Nov 2026](https://github.com/ggml-org/llama.cpp/blob/master/tools/imatrix/imatrix.cpp)

4. **H3 · Allocation. Est.** The ranking is testable after defining all three scores. Use the same candidate tensors, calibration, solver and byte cap. Compare measured end-to-end block loss, a sum of fixed-P single-visit costs, and a visit-blind cost built from first-visit statistics. Multiplying a first-visit score by visit count is a separate, cheap heuristic. Keep Unsloth as an external deployment comparator. If the two internal orderings fail, report which contrast failed. Additivity is a modeling assumption. Measure selected core/core and core/coda pairs and score the resulting whole builds on untouched examples. Use one budget around the 11.66 GB product first, subject to measured feasibility. Five block measurements cannot support 24 independent layer scores. Start with block allocation and promote only blocks whose internal ranking could change the decision.

5. **H4 · Router drift. Est.** Test whether same-layer top-8 Jaccard falls from visit one to three on the same prefixes at fixed P. A flat or improving contrast with a tight interval falsifies the claimed decline. Stratify by the reference’s rank-8/9 margin and report selected-expert weight changes alongside set overlap. If the first affected expert GEMM comes after an unchanged router, that router should agree on clean inputs. Use it as a sanity check. Teacher-forced replay removes differences in generated prefixes. Later route flips can still be a consequence of perturbed hidden states. A forced-reference-route replay can test whether those flips contribute to output loss, if the hook is cheap. Start with one affected block. **V.** Routing consistency is already a MoE quantization objective. [VSRAQ, 4 Jun 2026](https://arxiv.org/abs/2606.05688)

6. **H5 · Last-four-layer tolerance. Est.** Test B5 as a local noninferiority claim, with a margin fixed before the main run. For example, propose 0.001 nats per scored token and justify it against the measured conversion floor and the byte savings. An upper bound below the margin supports tolerance. A lower bound above it falsifies tolerance. A wide interval is inconclusive. Compare B5-only Q4 against unchanged source weights in the same runtime. Include an equal-layer NVFP4 coda control where possible. Position, source precision, block size, and downstream depth otherwise move together. **V.** TML reports the deployed 20/4 precision split. **Verify.** I found no vendor claim that post-training 4-bit requantization of the final sixth should be harmless. [TML launch, 20 Nov 2026](https://thinkingmachines.ai/news/inkling-2-mini/)
