Two blockers: slot weights in a later GGUF shard make the model unloadable, and a slot that replaces just one expert projection can make the GPU MoE cache read the other projection from the wrong bank.

I reviewed the pinned `29b52d3` checkout with all four patches applied. Both CPU tests passed at seed 42. I also loaded serialized GGUF fixtures through `llama_model_load_from_file_ptr` with mmap disabled and decoded mixed F32/NVFP4 and F32/Q8_0 fixtures. The shard, GPU cache, Metal, and mmap conclusions below are from source inspection.

1. **Blocker · Slot weights in later GGUF shards are skipped.** `load_arch_tensors()` checks `gguf_find_tensor(ml.metadata, ...)`, which searches the first shard. The real loader indexes every shard in `weights_map`, and `done_getting_tensors()` checks against that full count. Put `blk.24.ffn_gate_up_exps.weight` in shard 2 and the load fails with `wrong number of tensors`. A companion scale can still be found through the generic pass, leaving the count short by the weight alone. **Test:** Load the same fixture as a single GGUF and as two shards, with the slot weight and scale together in shard 2 and then on opposite shards. Require identical tensor bindings and logits with mmap on and off. 2. **Blocker · The GPU MoE cache can use a slot map from one bank to index another.** The cache groups layers by device and the types and shapes of all their expert projections, but stores only one binding per weight pointer. Use one GPU, host-resident experts, enough cache for both groups, and a `blk.24` that replaces only `gate_up` with Q8_0 while physical layer 6 uses F32. Both layers share the down pointer. The second group overwrites its binding. Layer 6 then populates and indexes its own bank while its down matmul reads the slot group’s bank. The same collision can occur across devices. The ordinary host-expert copy with the MoE cache disabled uses the actual source tensor and expert IDs. **Test:** Force both projections into host buffers, enable the cache with `n_ubatch=1`, and compare the per-pass MoE outputs against cache-disabled execution through cold fills and evictions. Test both one-projection variants. I reproduced successful loading and identical logits with and without the orphan scale. The input-scale variants are inconsistent too: with the corresponding owned weight, `down_exps.input_scale` loads and has no effect, while `gate_up_exps.input_scale` fails the tensor-count check. ## Response (Claude, 21 Nov 2026)

1. **Accepted.** The presence check now uses the loader's `weights_map` (every split) and falls back to the metadata only for metadata-only models (patch 0005). Our files are single-file, so no earlier result was affected.
2. **Rejected for this project, noted as a limitation.** The MoE cache is off by default (`moe_cache_size = 0`, `common/common.h:619`) and all pilot runs use full Metal offload. Our splicer always gives a slot both projections, so the one-projection collision cannot occur in our files. A patch for upstream use would need cache keys per (layer, slot).
3. **Open, out of scope.** Our files carry no `.scale` or `.input_scale` tensors, so orphan scales cannot occur. Validation of orphan scales would be needed before upstreaming.
4. **Accepted.** The comment was wrong; pass 2 over layer 6 is slot 24 (patch 0005). The scripts already used the correct formula (`scripts/perpass.sh`, `CLAUDE.md`).
5. **Rejected for this project.** No LoRA is used. Noted as a limitation.
6. **Rejected for this project.** No imatrix is collected on files with slot tensors; the imatrix comes from ggml-org's BF16.
7. **Rejected for this project.** No pruning.
8. **Rejected for this project.** The saver is not used; slot files are built by `scripts/splice.py`.
9. **Accepted in part.** The slot test now runs a 3-pass fixture and checks each pass and each projection separately, including that pass 2 and pass 3 slots differ and that a gate_up-only override with physical values is a no-op (patch 0006; 9 checks, 10 of 10 seeds). The low-stdev false failure is a property of the fixture; the default stdev is used.
10. **Accepted as the reason for the real-file controls.** The per-pass run (`scripts/perpass.sh`) includes two parity conditions on the real model, file format and Metal path: slot copies of the base values must reproduce the base logits, and all three passes via slots must reproduce the ordinary all-2-bit build.
