# Research sweep 2 (GPT-6.2 Sol, effort high, Codex CLI with web search, isolated; 2026-11-22)

## Prompt

Task: find inference-time or post-training tricks specific to looped / recurrent-depth models that interact with low-bit quantization: per-pass or per-iteration precision (different bits for different passes of the same weights), per-pass KV or state handling, adaptive pass count or early exit under quantization, error feedback or correction between iterations, per-iteration normalisation or gain correction, stability of the recurrence under weight noise (contraction, spectral norms). Include work on deep equilibrium models and recurrent nets if it transfers. For each: source, mechanism, evidence, and how it could be tested cheaply on Inkling 2 Mini in llama.cpp without retraining.
Context (all public): Inkling 2 Mini is an open-weight looped Mixture-of-Experts language model (Thinking Machines, Nov 2026). Its 24-layer stack runs layers 0-5 once, the core layers 6-17 three times with the same weights (P = 3 passes; passes 2 and 3 read the previous pass through small loop-control tensors), then layers 18-23 once. Experts ship in NVFP4. We quantize it to GGUF for llama.cpp on Apple Metal at about 11.5 GB (2-3 bit expert codes such as IQ2_S and IQ3_XXS, block scales). Our measured findings so far: (a) quantization error in the looped core is not additive across passes; (b) shrinking an expert's output gain (attenuation) compounds over the 48 layer visits; (c) a code refinement that minimises output error under the full per-expert input covariance (Gram) closes most of the gap to the best published quant on in-domain text but transfers poorly to reasoning traces when the Gram comes from one domain. Existing Inkling quants (Unsloth, bartowski, ggml-org, others) treat it as a plain transformer: no per-pass handling.
Rules for your answer: only cite sources you actually opened in this session, with the URL; mark anything you could not open as unverified. No speculation presented as fact. Be concise: a numbered list, then a short ranked recommendation.

## Reply (verbatim)

1. **Use different weight precision on different passes.** *A Tilted Bowl Is Not a Slippery Slope* reports that running the second half of Huginn’s loops in BF16 raised one 3-bit configuration from 3% to 40% on 100 GSM8K items, versus 42% for BF16. Fixed-depth Ouro gave mixed results, with no significant gain from INT8 finishing on surviving configurations at matched weight traffic. **Inkling test:** Keep all three passes and load a higher-precision copy of just one or two core expert tensors. Select it on pass 1, 2, or 3 by virtual layer index. Compare all three placements with uniform low precision and with the same tensors upgraded on all passes. Track resident bytes and decode time separately. LoopQuant also found that a 4/8-bit **activation** schedule beat flat 6-bit activations at the same average bitwidth on Huginn. That is a separate ablation with shared weight storage. [Finishing-pass experiments](https://arxiv.org/html/2609.39277) · [LoopQuant](https://arxiv.org/html/2610.16368)

2. **Calibrate one shared expert code across all passes and both domains.** Trajectory GPTQ pools input Grams across the deployed recurrence. On Huginn, simulated grouped INT3 GSM8K rose from 5.84% with first-step calibration to 20.70% with the full trajectory, or 17.44% at the same calibration row count. The same paper found Huginn’s loop-entry adapter especially sensitive to INT4. **Inkling test:** Bucket your existing per-expert Gram collector by pass and domain. At identical GGUF size and calibration token budget, compare your current Gram, raw pooling, and a mixture that gives prose and reasoning traces equal weight. Keep Inkling’s small loop-control tensors at reference precision for this sweep, then ablate them separately. [Feedback Exposure and Calibration Blindness](https://arxiv.org/html/2609.30820)

3. **Fit a gain per pass before adding a correction adapter.** LoopQ calibrates loop-dependent scaling and a boundary adapter that corrects the size and direction of the recurrent update. On Ouro-1.4B-Thinking at W4A4KV4, adding the adapter moved five-task mean accuracy from 57.46% to 58.96%. PTQD provides a simpler precedent from diffusion: regress out output-correlated quantization error at each step. **Inkling test:** On identical inputs and routes, fit one scalar per `(pass, layer)` to map the quantized MoE output to the higher-precision output. Apply it immediately before the post-MoE short convolution. Compare a shared scalar, per-pass scalars, and a scalar on the message injection. Evaluate all three on held-out reasoning traces before increasing the parameter count. [LoopQ](https://arxiv.org/html/2605.16343) · [PTQD](https://arxiv.org/html/2305.10657) · [Inkling MoE graph](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/src/models/inkling2.cpp)

4. **Profile KV by pass and layer, and test convolution state separately.** LoopKV profiles final-logit KL by `(loop, layer)`, then assigns cache precision or shares selected cells. Its Ouro-1.4B memory plan used 35% less KV storage than uniform INT4. FlashLoop compresses cross-pass KV differences, and LoopVQ jointly codes vectors across passes. **Inkling test:** Start with fake quantization of K and V separately, one pass at a time, using high-precision caches elsewhere. Rank by final-logit KL and verify the combined schedule on long-context retrieval. Then compare direct INT4 with INT4 deltas against pass 1. Inkling has distinct KV and short-convolution state slots per virtual layer, so leave convolution history intact during the KV sweep. [LoopKV](https://arxiv.org/html/2611.04137) · [FlashLoop](https://arxiv.org/html/2609.29812) · [LoopVQ](https://arxiv.org/html/2611.05304) · [Inkling loop graph](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/src/models/inkling2-loop.cpp)

5. **Use error feedback when quantizing the inter-pass state itself.** In frozen GRU and LSTM experiments, carrying forward the discarded rounding residual recovered much of the loss from deterministic 4-bit state writes. The LSTM’s cell state was particularly sensitive. **Inkling test:** Fake-quantize the pass-1 and pass-2 message banks at write time. Compare nearest rounding, stochastic rounding, and adding the first write’s residual before quantizing the second, with F16 write-back as the control. This isolates state-write error. Measuring expert-weight error requires a paired higher-precision computation. [Recurrent-State Write-Back](https://arxiv.org/html/2609.04490)

6. **Calibrate early exit under the deployed quant.** Huginn stopped when consecutive pass readouts had low KL, scoring 5.56 versus 5.63 on MT-Bench. Quantized puzzle models also benefited from a trained halt head followed by precise finishing, but that evidence used longer trajectories. **Inkling test:** First run whole sequences at fixed depths 1, 2, and 3 with both reference and low-bit weights. For an offline exit test, run the actual coda on pass-2 snapshots and see whether pass-1-to-2 KL predicts agreement with the three-pass reference. Benchmark token-wise exit only after defining how skipped tokens supply both later-pass KV and convolution history. Thinking Machines provides a separately trained variable-loop checkpoint as a control. [Huginn](https://arxiv.org/html/2502.05171) · [Quantized stop-and-finish](https://arxiv.org/html/2609.39277) · [Thinking Machines](https://thinkingmachines.ai/news/inkling-2-mini/)

7. **Measure finite-pass amplification before changing the recurrence.** DEQ Jacobian regularization improved solver convergence during training. In a small looped transformer, measured operator norms and spectral radii differed substantially, and low normalizer-input spread produced transient amplification. **Inkling test:** On a few teacher-forced prompts, inject the measured low-bit-minus-reference message error at one boundary and replay the remaining passes. Compare it with a norm-matched random direction and log state amplification, router flips, and final-logit KL. Probe the whole message-to-message map, including loop controls. These finite differences measure local sensitivity along the tested trajectory. [DEQ Jacobian regularization](https://proceedings.mlr.press/v139/bai21b/bai21b.pdf) · [Spectral Margins and Memory Routing](https://arxiv.org/pdf/2607.10681)

**Ranked recommendation:** First, compare pooled Grams and fit per-pass gains using the same captures. Second, run the three higher-precision placements and message-error replays. Third, profile KV if long-context memory is the bottleneck. Leave adaptive exit until the fixed-depth sweep shows a viable two-pass point. For any native NVFP4 reference, use a build containing llama.cpp’s fix for missing expert scales on passes 2 and 3. [llama.cpp PR #32704](https://github.com/ggml-org/llama.cpp/pull/32704)
