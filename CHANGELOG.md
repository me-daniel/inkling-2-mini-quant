# Changelog of the Counting Passes pre-registration

The pre-registration is version 1 of 20 November 2026 (private page, to be mirrored as `PREREG.md`). Its hypotheses, metrics and analysis are never edited in place. Every change or addition gets a dated entry here, written before the data it concerns.

## 2026-11-21: exploratory pilot before G0 (approved by Daniel, 21 Nov 2026)

**Status.** Exploratory. Nothing in this entry changes H1 to H5 or the confirmatory analysis. Data from this pilot are never used as confirmatory evidence. The design changes proposed by the 21 November review (`reviews/2026-11-21-plan-synthesis.md`) are not adopted by this entry; they get their own entry.

**Why.** Pin the tooling and measurement floors early, get a first pass-level result before others do, and decide whether a quantized model is worth releasing. Decided after a two-member council (`reviews/2026-11-21-council-*.md`).

**Model and engine.** `thinkingmachines/Inkling-2-Mini` at the revision downloaded on first use (hash recorded in `results/`). llama.cpp `29b52d3` (b12600) plus `patches/llama.cpp/` as recorded in `results/env.md`. All runs on the M5 Pro, one heavy run at a time.

**Data, fixed now.**
- **S (selection):** WikiText-2-raw test split, chunks 1 to 16 of 4,096 tokens in the model's tokenizer. Used for the block map, the pass sweep and the per-pass test.
- **T (held-out test):** T1 = WikiText-2-raw test chunks 17 to 32. T2 = reasoning traces generated by the Q8_0 reference at P = 3 (effort low, 2,048-token cap, temperature 0) from the first 20 GSM8K train questions, generated and hashed before any candidate model is built. Used only for the release comparison.
- **Reserved for the thesis:** everything else, including the rest of WikiText-2, GSM8K test and all task sets.
- S and T are checked for exact and near overlap with bartowski's v6 calibration text (the source of the imatrix). Overlap is reported, not hidden.

**Reference and metrics.** Reference: Q8_0 GGUF converted from the release at the same pass count P. Metrics: mean KL divergence and top-1 agreement against that reference, with a paired bootstrap over chunks (10,000 resamples, 95% CI). Absolute numbers are never compared with other repos' cards.

**Runs.**
1. **Floors.** Q8_0 against itself (run-to-run), and our IQ4_NL against Q8_0.
2. **Block map (P = 3, S).** Blocks B1 = L0-5, B2 = L6-11, B3 = L12-17, B4 = L18-19, B5 = L20-23. Each block's experts at a 2-bit level (IQ2_XXS gate_up, Q2_0 down) and a 3-bit level (IQ3_XXS gate_up, IQ4_NL down), all other tensors as in the Q8_0 reference. Built by splicing tensors between pre-quantized pool files.
3. **Pass sweep (S).** The uniform 2-bit and 3-bit pool builds at P = 2, 3 and 4, each against the Q8_0 reference at the same P. Mini rejects P = 1. P = 2 and 4 are outside what Mini was tuned for, so this is a pilot, not an H1 test, and no causal claim about the loop is drawn from it.
4. **Per-pass test (P = 3, S), block B2, 2-bit level, chosen now before any data.** Conditions: none, pass 1 only, pass 2 only, pass 3 only, all three. Outcome: the all-pass change in centred logits compared with the vector sum of the three single-pass changes, as a per-token residual ratio, plus KL. Requires the untie patch (per-slot tensors), which ships with a failing-without-it test.
5. **Release candidate.** Daniel picks the allocation from the S table and writes the choice and reasoning here before T is scored. Built at no more bytes than Unsloth `UD-IQ3_XXS` (mainline layout, 11,663,310,784 bytes), language-model file only (no mmproj, no drafter).

**Stop rules.**
- Stop everything if the Q8_0 run-to-run KL is not near zero, if P = 2/3/4 do not change runtime in line with 36/48/60 layer visits, or if our IQ4_NL against Q8_0 is outside 0.005 to 0.02 KL.
- Drop the per-pass test (report the failure instead) if a no-op splice does not reproduce baseline logits exactly, or if switching all three passes does not reproduce an ordinary build with the same tensors.

**Upload gate (all required, on T).** Paired KL better than both a same-size uniform build and `UD-IQ3_XXS` (same binary), 95% CI excluding zero; top-1 not worse; clean stability checks: llama-server chat smoke test, 30 GSM8K prompts with a token cap, ten 2,000-token generations at temperature 1.0, one prompt of at least 16K tokens, JSON tool-call validity, two non-English prompts. If any fails: publish the measurements without a model.

**Card wording.** May say: "block-wise allocation chosen from a measured 5-block table at P = 3", exact bytes, tokens, reference and commit, "exploratory". May not say: "loop-aware", "pass-aware", "first", "best", any task-quality claim, any comparison with numbers on other repos' cards, any causal claim about the loop from the pass sweep. The per-pass result may be reported only as "on these documents, at P = 3, changing B2's experts on pass k produced this measured logit change".

**Publication.** Uploads and any public note need Daniel's explicit go at the time.

### Addendum A (2026-11-21, approved by Daniel): linearity-theorem analysis

Exploratory, same status as the entry above. Based on the linearity theorem of Malinovskii et al. (arXiv 2411.17525).
- For every block b and level, compute the relative l2 error t_b = sum ||W_q - W||^2 / sum ||W||^2 over the block's routed-expert weights, with W the Q8_0 reference weights, dequantized from the GGUF files. Also report a variant weighted by per-expert routing counts from the imatrix.
- Fit alpha_b = dKL_b / t_b on S from the block map. Report the linear prediction sum_b alpha_b t_b against the measured KL of the release candidate (and of any mixed build measured).
- Per-pass test: two more conditions on block B2, perturbed with Gaussian noise of the same relative l2 error as the 2-bit level: tied (the same draw on all three passes) and independent (a different draw per pass). Seeds fixed in the script before running. Prediction under the theorem's additivity: independent ~ sum of single-pass effects; tied larger if the cross-pass terms are positive.
- The release allocation may use dynamic programming over alpha_b t_b under the byte budget, written by Daniel.

### Addendum B (2026-11-21, approved by Daniel): base of the per-pass test

The per-pass and noise conditions (run 4 and Addendum A) use our IQ4_NL build as the base instead of the Q8_0 reference: on a Q8_0 base, "pass 1 only" needs Q8_0 copies of layers 6-11 for passes 2 and 3 (about 36-41 GB), above the memory limit. Block B2's 2-bit tensors come from the 2-bit pool; all other tensors stay as in the IQ4_NL build. The outcome (residual ratio) is computed relative to the IQ4_NL base at P = 3; KL of every condition against the Q8_0 reference at P = 3 is also reported.

**Operating limits (approved 21 Nov):** single runs up to 32 GB of memory, one heavy run at a time; up to 350 GB of disk in `models/`; about 14-18 h of unattended Mac runs; up to 10 light and 3 heavy support-model calls; no extra downloads; no GCP. Uploads and public posts still need Daniel's go at the time, private repository first.
